# 单词测试云同步：第一阶段

## 范围

第一阶段让错题记录与单词掌握度可以通过用户主动操作一起同步。提供拉取并合并、合并上传和覆盖云端三种操作；设置仍走现有的独立同步。离线时本地测试和复习继续可用，联网或登录本身不会触发上传。

本阶段不保存完整测试历史，也不能跨设备继续未完成的测试。答题总数、正确率和完整题目顺序仍不是云端同步数据。

## 快照与旧数据兼容

快照继续使用现有的 `schemaVersion: 2` 错题本格式，并增量加入 `learningSchemaVersion: 1` 和 `masteryRecords`。读取端兼容错题本 v1、v2 快照；旧快照没有掌握度字段时按未提供掌握度读取，不把它解释为用户主动清空了进度。

旧客户端合并上传时，云端与本地错题事件仍按事件 ID 合并。旧客户端覆盖上传时，如果请求没有 `masteryRecords`，服务端会尽可能保留仍能关联到上传错题及其有效错题事件的云端掌握度。显式提供掌握度的客户端则按该快照执行覆盖。

掌握度按单词 ID 保存为完整记录。同步选择较新的记录；时间相同时使用固定、可重复的裁决规则。不会相加复习次数，也不会取最大的连续答对次数。两台设备各自复习后，较旧的一份进度可能被舍弃；第一阶段没有答题事件历史来重建并行进度。

每条掌握记录通过 `wrongAttemptIds` 绑定它所对应的错题事件。删除错题后，即使较旧设备保留了带有未来时间戳的掌握记录，该记录也不会附着到后来重新加入的错题周期。

## 并发写入与备份

云端写入使用对象 ETag 做条件更新：首次创建要求对象仍不存在（`If-None-Match: *`），更新要求 ETag 未改变（`If-Match`）。合并上传遇到版本冲突会重新读取、合并并尝试写入，最多尝试三次；耗尽后返回同步冲突。覆盖上传先核对用户确认时读取的版本，版本已变化或条件写入冲突时返回冲突，不自动重试，以免无提示地覆盖新数据。

更新当前快照前会先备份已有快照，并保存本次候选快照的备份。任一备份失败都不会写入当前快照。候选备份代表“准备写入的结果”，不代表该结果已经成为当前版本；例如条件写入冲突后，它可能仍留在备份目录中。

请求体和合并后的快照上限为 5 MiB。为避免旧版 `wrongCount` 在解析时展开成过量事件，快照中的待展开事件总数另限为 50,000；负数计数会按无效错题数据拒绝。超限快照会被拒绝，不会写入备份或当前快照。

## 本地应用与账户目标

错题记录、掌握度和成功上传的确认快照现保存在 `henguren-v3` v3 的同一账户分区中。本地同步应用与上传确认在同一个 IndexedDB 事务中提交；写入失败时不会留下只更新一类数据的结果，界面提示本地应用失败，可显式重试。

覆盖前会再次核对确认时选择的账户或开发者同步目标，服务端也会检查请求账户与当前登录账户是否一致。本机错题和掌握度按稳定的账户 ID 分区，访客数据保存在独立分区；设置、语言、主题及离线缓存继续属于设备。

成功的账户合并上传或覆盖上传会记录服务端确认的快照。主动退出成功，或确认登录另一账户时，仅清理与该确认快照完全一致的错题和对应掌握度；任一内容变化就保留整组。已经上传且完全相同的删除标记也可清理；本机副本清理不会生成新的删除标记，不会删除云端数据。未上传修改留在原账户分区，新账户与访客均不可见，重新登录原账户可继续使用。

会话过期、离线、身份请求失败、登录取消或上传失败不会触发清理。会话过期后继续使用原账户分区；离线时主动退出会提示暂不可用。上传成功但本地确认写入失败时保守地保留数据，不因猜测上传成功而清理。拉取云端不是成功上传确认，因此单纯拉取的数据不会因此被清理。

旧版两个数据库会兼容迁移：先阻止旧版客户端继续写入，把错题与掌握度持久化到访客分区，再清除旧存储副本。已提交的迁移状态保证重试不会覆盖现有分区。无归属的旧数据不会自动归给第一个登录账户；用户可在用户页明确确认，将访客数据转入当前账户的本地分区，之后仍需手动上传。

分区切换与清理原子提交，并通知其他标签页重新加载。旧页面的后续写入会核对持久化的当前归属，不会把尚未完成的答题或同步回调写到新账户。阻止数据库升级的旧标签页需要关闭后重试。分区是产品的数据归属规则，不是本机加密或浏览器使用者之间的安全边界。

开发者自定义同步源不构成账户上传确认，不会让账户数据因为上传到自定义桶而在退出时被清理。上传确认代表当时成功保存（包含备份），不保证当前云端版本永远未被其他设备修改；清理后的数据重新使用需手动拉取。

## 开发者自定义 R2

开发者模式通过浏览器直接访问自定义 R2。存储桶的 CORS 规则需要允许请求头 `If-Match` 与 `If-None-Match`，并在响应中暴露 `ETag`。缺少请求头许可或 ETag 暴露时，浏览器可能阻止条件写入或客户端无法读取版本号。

## 验证状态与后续工作

当前实现不新增依赖。自动化测试覆盖旧快照兼容、掌握度合并、删除后重新加入、条件写入冲突、备份失败、5 MiB 限制和 50,000 条事件上限。真实 Cloudflare R2 的联调尚未执行，因此部署环境中的 CORS、凭据和条件写入行为仍需在隔离测试桶中验证；本阶段没有向真实 R2 写入数据。

本阶段独立快照通过 85 项测试（含 18 项新增同步测试和 7 项归属清理测试）、lint、类型检查和生产构建。浏览器使用隔离测试数据及模拟云端，验证了两个同步入口、拉取掌握度、覆盖确认与取消、确认期间版本变化、备份失败、本地事务失败后的重试、未登录与离线禁用，以及移动端弹窗布局；未出现页面运行时异常。实际未登录路由返回 401，并设置禁止缓存响应。

账户归属的生产页面浏览器验证覆盖：旧数据库迁移至访客分区、明确确认转入账户、不自动上传、上传后未修改数据清理、修改过掌握度的整组保留、会话过期与离线保留、主动退出、账户间隔离、重新登录原账户继续使用、切换账户清理、多标签页重新加载，以及旧标签页阻止升级时保留数据、关闭后重试迁移成功。本地事务故障模拟确认数据和上传确认标记都不发生部分提交。

主工作区构建的字体字节校验曾因 Windows 换行失败。验证在仅包含本阶段暂存内容的隔离副本中执行，使用已有字体生成命令恢复副本的标准字节，并调整副本的 Turbopack 根目录以容纳已有依赖链接后构建通过。生成结果与仓库原始字体产物一致；这些环境处理未纳入提交，主工作区的字体、构建配置和其他未提交工作均保留。

完整测试历史、跨设备续测，以及基于答题事件合并并行复习进度，留待后续阶段设计。
